# Megan — Ethereum Meme-Coin Research

مخزن توسعه ربات پژوهش و کشف زودهنگام میم‌کوین‌ها؛ زنجیره فعال فعلی فقط Ethereum Mainnet است.

## وضعیت فعلی
- [کشف قراردادها و استخرها](src/megan_watcher.py): اسکن بلوک، CREATE مستقیم، CREATE/CREATE2 داخلی از طریق trace و رویدادهای factoryهای V2/V3 که پیکربندی شده باشند.
- [اتصال منابع عمومی بازار](src/public_sources.py): GeckoTerminal، DEX Screener و Honeypot.is.
- [موتور ارزیابی ریسک](src/risk_engine.py): امتیاز ریسک و فرصت، موانع سخت، هشدارها و داده‌های نامعلوم.
- [تحلیل وضعیت LP](src/lp_analysis.py): تفکیک توکن‌های LP قفل‌شده، آزاد، سوزانده‌شده و نگهداری‌شده در قراردادهای ناشناخته؛ فقط با snapshot کامل و lock record تأییدشده. این ماژول فعلاً تحلیل‌گر داده ورودی است و هنوز به RPC/locker registry متصل نشده است.
- [تحلیل هولدرها](src/holder_analysis.py): محاسبه تمرکز ۱۰ هولدر بر اساس snapshot کامل و قابل تطبیق با totalSupply؛ تفکیک burn، جفت‌ارز LP و locker تأییدشده از عرضه در گردش. این ماژول هنوز به گردآوری زنده Transfer logs و balanceOf متصل نشده است.
- [اسکنر پژوهش](src/megan_research.py): کشف استخرهای تازه Ethereum، دریافت داده‌های بازار و ذخیره گزارش در SQLite.
- [آزمون‌ها](tests/) و [GitHub Actions](.github/workflows/python-tests.yml).

## نصب و اجرا
Python 3.11 یا بالاتر:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
python -m pytest -q
```

### کشف قرارداد و استخر در زنجیره
`ETHEREUM_RPC_URL` را در `.env` تنظیم کنید. برای دیدن CREATE2 داخلی، RPC باید trace API داشته باشد. به‌صورت پیش‌فرض `TRACE_REQUIRED=true` است؛ اگر trace در دسترس نباشد، اسکنر جلو نمی‌رود تا بلوک‌های ناقص را بی‌صدا رد نکند. فقط در صورت پذیرش صریح پوشش ناقص، آن را `false` کنید:

```bash
megan-watch
```

### snapshot هولدرهای ERC-20 از Ethereum

برای استخراج آدرس‌های شرکت‌کننده در رویدادهای Transfer از بلاک استقرار تا بلاک snapshot، سپس خواندن balanceOf و تطبیق با totalSupply:

```bash
megan-holders --token 0xTOKEN_ADDRESS --deployment-block 19000000 --chunk-size 2000
```

RPC باید آرشیو لاگ‌های بازه موردنیاز را ارائه کند؛ اجرای تست‌ها با mock RPC است و جای اجرای زنده روی شبکه را نمی‌گیرد. خروجی فقط زمانی complete می‌شود که بلاک snapshot در طول خواندن reorg نشده باشد و مجموع balanceOfها دقیقاً با totalSupply برابر شود. این دستور فقط خواندنی است. آدرس‌های LP pair و locker تا زمان ارائه شواهد مستقل، به‌صورت خودکار مستثنا نمی‌شوند. برای توکن‌های rebase، reflection، یا توکن‌های غیر استاندارد، عدم تطبیق به UNKNOWN منجر می‌شود.

### بررسی LP توکن‌های Uniswap V2

برای خواندن توکن LP جفت‌ارز V2 از بلاک ایجاد جفت تا بلاک snapshot:

```bash
megan-lp --pair 0xPAIR_ADDRESS --created-block 19000000
```

این دستور موجودی مستقیم EOAها، آدرس‌های burn و موجودی نگهداری‌شده در قراردادها را جدا می‌کند. موجودی قراردادها تا زمان تأیید locker و مقدار/زمان قفل، UNKNOWN می‌ماند. این ابزار برای Uniswap V3 نیست؛ V3 از position NFT استفاده می‌کند و آداپتور جداگانه می‌خواهد.

### اسکن NFTهای نقدینگی Uniswap V3

```bash
megan-v3 --from-block 12369621 --to-block 19000000
```

`--from-block` باید بلاک استقرار Position Manager یا یک بلاک قبل از اولین mint موردنظر باشد؛ اسکن ناقص، تاریخچه کامل NFTها را تضمین نمی‌کند. ابزار رویدادهای ERC-721، مالک فعلی، جفت توکن، fee tier، محدوده tick و liquidity خام را می‌خواند. مالک EOA به‌عنوان custody آزاد و مالک قراردادی بدون مدرک به‌صورت UNKNOWN گزارش می‌شود.

برای ارزیابی lockerهای قراردادی، فایل JSON جداگانه‌ای بر اساس ABI و bytecode hash تأییدشده همان قرارداد بسازید. ابزار فقط وقتی lock را می‌پذیرد که hash کد با registry تطبیق کند و دو تابع read-only تنظیم‌شده، قفل فعال و زمان آزادسازی را در همان بلاک تأیید کنند. registry نمونه عمداً خالی است؛ هیچ آدرس locker یا امضای تابعی از پیش به‌عنوان معتبر معرفی نشده است.

### بررسی سابقه Deployer ثبت‌شده در دیتابیس محلی

```bash
megan-deployer --creator 0xCREATOR_ADDRESS --db data/megan.sqlite3
```

این گزارش فقط قراردادهایی را نشان می‌دهد که اسکنر قبلاً در دیتابیس ثبت کرده است؛ اگر بازه اسکن کامل نباشد، سابقه ناقص است. تعداد Rugها و ارتباط کیف‌پول‌های تأمین‌کننده مالی از این داده به‌تنهایی قابل اثبات نیست و UNKNOWN باقی می‌ماند.

### اسکن منابع عمومی بازار
بدون کلید خصوصی و بدون اتصال کیف‌پول:

```bash
megan-research --once
megan-research --interval 30
```

خروجی هر نامزد به‌صورت JSON چاپ و در `data/megan.sqlite3` ذخیره می‌شود.

## اصل امنیتی مهم
قفل‌نبودن نقدینگی به‌تنهایی «فرصت خرید» نیست؛ یعنی امکان خروج نقدینگی وجود دارد. موتور آن را ریسک محسوب می‌کند. نبود داده هرگز به‌عنوان امن‌بودن تفسیر نمی‌شود. شکست شبیه‌سازی فروش یا تشخیص Honeypot مانع سخت است. امتیازها heuristic هستند و جای بررسی مستقل را نمی‌گیرند.

## محدودیت نسخه حاضر
این نسخه یک MVP پژوهشی است، نه شکارچی خودکار سود و نه سامانه آماده سرمایه‌گذاری. کشف استخرهای تازه را از GeckoTerminal می‌گیرد؛ پوشش همه factoryهای اختصاصی و قراردادهای فاقد استخر تضمین نشده است. DEX Screener اطلاعات جفت‌ارز و فعالیت می‌دهد، اما تعداد خرید/فروش آن معادل تعداد کیف‌پول‌های یکتا نیست. بررسی قفل LP، snapshot کامل هولدرها، تحلیل bytecode/proxy و اختیارات مدیریتی، سابقه deployer، تشخیص خوشه کیف‌پول‌ها، شبکه اجتماعی تلگرام و رتبه‌بندی چندمرحله‌ای هنوز نیازمند تکمیل و اعتبارسنجی‌اند. وضعیت این فیلدها فعلاً UNKNOWN است.

«کل اینترنت» یا «کل تلگرام» قابل اسکن تضمین‌شده نیست؛ باید منابع عمومی مشخص، مجوز دسترسی، محدودیت نرخ و روش ثبت شواهد تعریف شود. پایش تلگرام در این نسخه پیاده‌سازی نشده است.
